# SALICON Annotator

SALICON（Jiang et al., "SALICON: Saliency in Context", CVPR 2015）のマウス追跡による注視データ収集方式を再現したデスクトップアプリです。Tauri 2 + React で作っています。UI 画像やキャラクターイラストに対する注視データを集め、`model/` のファインチューニング用データに変換します。

## 使い方

1. 「本番用」に画像フォルダー、「保存先」に結果を書き込むフォルダーを選ぶ（練習用は任意）
2. 参加者 ID と実験条件を入力し、「セッションを始める」を押す
3. 参加者は各画像の前に中央の赤い点をクリックし、ぼやけた画像をマウスで自由に眺める
4. 結果は `保存先/{参加者ID}_{日時}.json` に、試行ごとに上書き保存される（途中で終了してもそこまでは残る）
5. 終了後、画像ごとのヒートマップで記録を確認できる。Esc で中断でき、中断までの試行も保存される

画像 ID にはファイル名の stem（拡張子を除いた部分）を使います。

## 論文の方式と実装の対応

| 項目 | 論文 | 本実装 |
| --- | --- | --- |
| 表示 | 6 段のガウシアンピラミッドを、マウス位置を中心に混合した多重解像度画像 | WebGL2 で同じ構成を GPU 描画 |
| 解像度関数 | R = α / (α + θ)、α = 2.5°、p = 7.5 px/度（640x480 画像） | 同じ式と既定値。段の間は線形補間（論文は Geisler & Perry の伝達関数） |
| カーソル | 半径 2° の赤い円。開始時は画像中央 | 同じ。中央の点をクリックして開始し、中央から始まるようにした |
| 提示時間 | 5 秒、試行間 2 秒、ランダム順 | 既定値は同じ（画面で変更可） |
| 課題 | 自由観察 | 同じ |
| 練習 | 実験室条件で 10 枚 | 練習用フォルダーで指定 |
| 後処理 | 12 Hz 未満を破棄、PCHIP で 100 Hz に再標本化、速度の大きい半分を除去、ガウシアンでぼかす | 同じ。マウスイベントは動いたときしか出ないため、開始位置（中央）と最後の位置を提示終了まで保持してから再標本化する。σ は論文に記載がないため既定 1 度 |

論文の参加者数は 1 画像あたり 60 人です。少人数ではマップが疎になるため、人数を確保するか、σ を大きめにしてください。

### 1 度あたりの画素数

**画像の元解像度** で指定します。論文は 640 px 幅の画像に 7.5 を使っています。大きな画像で論文と同じ見え方にするなら、画像幅に比例させてください（例: 1280 px 幅なら 15）。

## 学習データへの変換

```bash
pip install numpy scipy pillow
python tools/export_dataset.py results/*.json --out ../model/data/my_ui_dataset --split train --images-dir path/to/images
```

`maps/{split}/{id}.png`（連続値）と `fixations/{split}/{id}.png`（2 値）を出力します。`--images-dir` を指定すると画像も `images/{split}/` にコピーします。

被験者は `participantId` で区別し、`--min-observers` は重複を除いた人数で判定します。同じ被験者が同じ画像を複数回見ている場合、既定では最初の試行だけを使います（`--repeat all` で全試行）。

## 記録されるデータ

`SessionResult`（`src/lib/types.ts`）の JSON です。

- `trials[].samples`: 実測したマウスイベントの `{ t, x, y }`。`t` は提示開始からの ms、`x`・`y` は画像の元解像度の画素
- `trials[].startGaze`: 提示開始時の注視点（中央クリックで開始した場合は画像中央）
- `trials[].quality`: 平均サンプリング周波数、12 Hz 基準の可否、画像外にいた時間、フォーカス喪失、未操作
- 表示サイズ、`devicePixelRatio`、User-Agent、フォビエーションのパラメーター

## 開発

前提: Node.js 20 以上、Rust（stable）、[Tauri の前提パッケージ](https://v2.tauri.app/start/prerequisites/)。

```bash
npm install
npm run tauri dev      # アプリを起動
npm run tauri build    # インストーラーを作成
npm run dev            # ブラウザーで画面だけ確認（ファイル選択とダウンロードで代替）
npm test               # 後処理の単体テスト
cd src-tauri && cargo test
```

### 構成

```
annotator/
├─ src/
│  ├─ lib/            # 再利用できる React コンポーネントと後処理（SaliconAnnotator, SaliconSession, processing）
│  ├─ App.tsx         # 設定・実行・結果確認の画面
│  └─ backend.ts      # Tauri コマンドの呼び出し（ブラウザーでは代替動作）
├─ src-tauri/         # Rust 側（画像一覧・画像読み込み・結果保存のコマンド）
└─ tools/export_dataset.py
```

画像は Rust 側でバイト列として読み、Blob URL にして表示します。asset プロトコルを使わないのは、WebGL のテクスチャーに別オリジンの画像を使うと CORS 制約に当たるためです。

## 注意点

- 実験条件をそろえるため、表示幅は固定し、同じ画面環境で実施してください。
- タッチ操作では指で画面が隠れるため、マウスでの実施を推奨します。
- 論文の AMT 版にあった、ブラウザー性能チェックや視線データとの比較による品質管理（gold standard）は含めていません。必要であれば、既知の画像を混ぜて `quality` と合わせて判定してください。
